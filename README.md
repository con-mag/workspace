# المركز — نظام العمل والمعرفة

نسخة عامة تعمل كواجهة ثابتة على GitHub Pages، بينما البيانات المشتركة وعمليات الإضافة/التعديل/الحذف تمر عبر **API خادمي** يتصل بمستودع GitHub.

## البنية

- **GitHub Pages:** الواجهة والملفات العامة.
- **GitHub Repository:** مخزن النسخة المشتركة للملفات و`data/custom.json`.
- **API Serverless:** بوابة آمنة أمام GitHub REST API؛ لا يوضع GitHub Token في المتصفح.
- **Polling:** الأجهزة المفتوحة تتحقق دوريًا من أحدث حالة، مع زر تحديث يدوي.

GitHub يتيح إنشاء/تحديث ملف في المستودع عبر REST API باستخدام Fine-grained token بصلاحية Contents: write، مع اشتراط SHA عند تحديث ملف موجود. لذلك لا يجب وضع التوكن في JavaScript الواجهة.  
المصدر: https://docs.github.com/en/rest/repos/contents

## إعداد GitHub

1. أنشئ مستودعًا عامًا أو خاصًا حسب احتياجك. عند استخدام GitHub Pages يجب أن تكون الملفات التي تريد عرضها للزائر متاحة للنشر.
2. انسخ محتويات مجلد `site/` إلى جذر مستودع GitHub Pages.
3. تأكد أن مجلد `clients/ريتاج علي/` موجود كما هو، بما في ذلك الفروع والملفات المرفقة.
4. فعّل GitHub Pages من الفرع المطلوب.

## إعداد API

النسخة المرفقة تتضمن الآن `api/index.js` جاهزًا للنشر كـ Vercel Serverless Function.  
إذا تركت `API_BASE` فارغًا، تعمل مساحة العميل بوضع محلي داخل المتصفح باستخدام IndexedDB: يمكنك إنشاء المجلدات ورفع الملفات وفتحها وتعديل النصوص، لكن هذه التغييرات لا تنتقل إلى GitHub ولا إلى جهاز آخر.

للمزامنة الحقيقية بين الأجهزة، انشر مجلد `api/` واربط `API_BASE` بعنوانه.

متغيرات البيئة المطلوبة:

```text
GITHUB_OWNER=اسم الحساب أو المنظمة
GITHUB_REPO=اسم المستودع
GITHUB_BRANCH=main
GITHUB_TOKEN=Fine-grained token
ADMIN_PASSWORD=1122
SESSION_SECRET=سلسلة طويلة عشوائية
ALLOWED_ORIGIN=https://اسمك.github.io
```

### صلاحية GitHub Token

استخدم Fine-grained Personal Access Token مقيدًا بالمستودع المطلوب فقط، مع:

- Contents: Read and write

ولا تمنح صلاحيات إضافية لا يحتاجها النظام. GitHub توصي باختيار أقل الصلاحيات الممكنة وعدم استخدام Classic token عندما لا تكون هناك حاجة إليه.

المصدر: https://docs.github.com/en/rest/authentication/keeping-your-api-credentials-secure

## إعداد الواجهة

في:

```text
site/js/config.js
```

ضع عنوان الـAPI:

```js
window.APP_CONFIG = Object.freeze({
  API_BASE: "https://YOUR-API-DOMAIN.vercel.app/api",
  POLL_MS: 15000,
  APP_NAME: "المركز"
});
```

لا تضع GitHub Token أو Secret أو كلمة مرور الإدارة داخل `config.js`.

## كلمة المرور

الواجهة تستخدم كلمة `1122` كاعتماد للإضافة والتعديل والحذف، لكن الكلمة الحقيقية لا تُحفظ في الواجهة؛ التحقق يتم في الـAPI الخادمي، وتصدر جلسة مؤقتة بدل إرسال كلمة المرور مع كل عملية.

**ملاحظة أمنية:** `1122` نفسها كلمة مرور ضعيفة جدًا بسبب قصرها. النظام لا يخزنها في الواجهة، لكن لا يمكن اعتبار كلمة من 4 أرقام حماية قوية أمام مهاجم مصمم. يمكن تغييرها من متغير البيئة `ADMIN_PASSWORD` دون تعديل الموقع.

## الملفات داخل مساحة العميل

عند فتح عميل مثل ريتاج:

- تظهر المجلدات كعناصر مرئية.
- النقر على مجلد يدخل إليه.
- النقر على ملف يفتح عارضه.
- ملفات TXT/MD والنصوص المشابهة قابلة للتحرير.
- DOCX/XLSX/PDF وغيرها تُفتح أو تُنزّل كملفات فعلية.
- يمكن إنشاء مجلد.
- يمكن إنشاء TXT/MD مباشرة.
- يمكن رفع DOCX وغيرها من الملفات المسموح بها.
- يمكن حذف الإضافات من مساحة العميل بعد تأكيد وكلمة المرور.

الملفات التي جاءت مع مرفق ريتاج الأصلي لا يظهر لها زر حذف في الواجهة الافتراضية، حتى لا تختلط الإضافات الجديدة بالهيكل الأصلي.

## المزامنة بين الأجهزة

عند الربط الصحيح:

```text
جهاز 1
  ↓
API
  ↓
GitHub Repository
  ↓
جهاز 2 / الهاتف
```

الأجهزة المفتوحة تفحص الحالة الجديدة دوريًا. لذلك إذا أضفت ملفًا من جهاز، سيظهر على الأجهزة الأخرى بعد وصول النسخة الجديدة من المستودع، أو فور استخدام زر «تحديث».

هذه ليست Realtime push network مثل WebSocket؛ إنها مزامنة مشتركة مبنية على GitHub API مع polling. وهي متعمدة هنا لتبقى البنية متوافقة مع GitHub Pages بدل إضافة قاعدة بيانات منفصلة.

## حدود عملية الرفع

هذه النسخة تضع حدًا محافظًا قدره 4MB للرفع عبر الـAPI. الملفات الكبيرة جدًا يفضّل تخزينها خارج هذا المسار أو استخدام آلية تخزين متخصصة.

## لا تضع أسرارًا في المستودع

لا ترفع:

- GitHub Token
- Session Secret
- كلمات مرور
- `.env`

إلى GitHub.


### قالب مساحة ريتاج

تم تنظيف أسماء المجلدات العربية من محارف RTL/Bidi غير المرئية، والحفاظ على الهيكل المرفق في قالب `Retaj - Facebook Page Management`.  
المساحة تظهر في الواجهة كمستعرض ملفات ومجلدات بدل صفحة فارغة، مع دعم:
- مجلدات متداخلة.
- إنشاء مجلدات جديدة.
- رفع TXT / PDF / Word / صور وغيرها من الامتدادات المسموح بها.
- معاينة الصور وPDF.
- تحرير الملفات النصية وحفظها.
- فتح/تنزيل الملفات.
